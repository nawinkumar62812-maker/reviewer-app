# Product & Technical Specification: Blinded Review Portal

A production-grade, secure, blinded evaluation platform designed for academic, scientific, and engineering benchmark studies. Study administrators can upload ZIP review sets containing hundreds of items (such as the T7 hardware benchmark set), configure review rubrics, generate cryptographically secure tokenized links, track reviewer progress in real time, and export unified CSV/Excel/JSON audit datasets. Reviewers access a distraction-free, zero-friction, mobile-optimized workspace with autosave, local resilience, and rigorous blinding guarantees.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> The following architectural decisions were aligned during Phase 1 interactive clarification and govern the implementation:

- **Backend Architecture**: Full-stack Node.js / Express server running on port 3000 with persistent database storage, server-side ZIP processing, token validation, and autosave sync endpoints.
- **Review Item Ordering**: Shuffled / randomized order per reviewer (using deterministic seeded shuffle tied to the reviewer token) to prevent evaluation fatigue and order bias across repeating benchmark requirements.
- **Reviewer Link Security**: Cryptographically secure tokenized URLs (`/review/:token`), with instant one-click revocation, expiration controls, and granular status monitoring by the administrator.
- **Question Schema & Extensibility**: Pre-configured with the standard T7 6-question hardware evaluation schema (with conditional display and automatic `na` filling), backed by a visual schema builder and CSV rubric importer for arbitrary review domains.

## 1. Product Overview

### 1.1 App Name Suggestions
1. **BlindReview OS** (Recommended: professional, authoritative, research-grade)
2. **Kanon Review Portal** (Clean, academic, focused on gold-standard evaluation)
3. **DoubleBlind HQ** (Emphasizes protocol integrity and uncompromised blinding)
4. **EvalVault** (Focuses on secure benchmarks and tamper-proof response storage)

### 1.2 Target Users & Personas
- **Study Administrators / Lead Researchers (Me)**: Engineering managers, benchmark creators, and scientific study leads coordinating multi-reviewer human evaluations. Needs bulk ZIP ingestion, quick link distribution, live completion telemetry, and 1-click combined exports.
- **Peer Reviewers & Domain Evaluators (Other People)**: Hardware engineers, domain specialists, and academic reviewers. Non-technical in terms of app tooling; requires zero sign-up barrier, intuitive UI across mobile and desktop, zero data loss, clear rubrics, and rapid keyboard/touch navigation.

### 1.3 Core Problem Solved
Traditional blinded peer reviews rely on emailing spreadsheets, fragile local Python scripts (like terminal-based labellers), or cumbersome enterprise forms that expose unblinded metadata, lack autosave, cause duplicate answers, or require complex logins. The Blinded Review Portal provides a frictionless web experience where reviewers simply tap a personal link, confirm their details, and review items in a clean distraction-free UI with continuous autosave and offline protection, while the admin retains complete oversight and zero risk of information leakage (e.g. formal outcomes or author identities).

## 2. Core Features

### 2.1 Admin Features
- **Dataset Ingestion Engine**:
  - Drag-and-drop upload of ZIP archives up to 100 MB.
  - Server-side extraction and validation (verifies `items/R###.json` structure, scans for 320 items or custom sets).
  - Sanitization pipeline: strips `formal_outcome` and `evidence_logs` from all reviewer-facing payloads, scrubs AI watermarks (e.g., `"Author: generated by ChatGPT"`), and prepares sanitized cache.
- **Rubric & Question Schema Manager**:
  - Pre-loaded with the **T7 6-question hardware benchmark rubric**:
    - **Q1**: Clarification question relevant to requirement? (`yes` / `no` / `na`)
    - **Q2**: Identifies intended ambiguity? (`yes` / `no` / `na`)
    - **Q3**: Oracle answer faithful to frozen text & only answers question? (`yes` / `no` / `na`)
    - **Q4**: RTL follows oracle answer? (`yes` / `no` / `partly` / `na`)
    - **Q5**: RTL introduces unrelated assumptions? (`yes` / `no`)
    - **Q6**: Main failure cause (`ambiguity` / `implementation` / `syntax` / `interface` / `formal-tool-limit` / `none`)
  - Dynamic visual editor to add, reorder, or edit questions, input types (single-choice, multi-choice, text, scale), and conditional logic (e.g., skip Q1–Q3 if model question is empty).
- **Secure Link Generation & Distribution**:
  - Batch generate unique review tokens with custom reviewer names, email pre-fills, or open-seat invite tokens.
  - One-click copy, email mailto generator, and direct WhatsApp sharing links.
  - Token status: `Active`, `Paused`, `Revoked`, `Expired`.
- **Live Reviewer Telemetry Dashboard**:
  - Live state tracking: `Link Created` $\rightarrow$ `Details Submitted` $\rightarrow$ `Review Started` $\rightarrow$ `In Progress (X/320)` $\rightarrow$ `Submitted`.
  - Last active timestamp, completion percentage bar, and elapsed review time.
  - Management actions: resend link, revoke access, reset progress, delete test/duplicate submissions.
- **Export & Audit Center**:
  - Download individual reviewer CSV (compatible with official `review_form.csv`).
  - Download combined master CSV with all reviewer responses side-by-side or stacked.
  - Download full JSON backup containing responses, timing metadata, and notes.

### 2.2 Reviewer Features
- **Zero-Barrier Access**: Single-click URL opening in any modern browser (Chrome, Safari, Firefox, Edge, iOS Safari, Android Chrome). No account creation or password required.
- **Onboarding & Consent**: Welcome screen collecting Full Name, Gmail/Email address, and optional affiliation/ID, plus explicit study consent.
- **Blinded Evaluation Workspace**:
  - Requirement specification card with clean typography and collapsable module ports.
  - Clarification exchange card showing Model Question and Oracle Answer (or clean muted indicator if none).
  - Generated RTL code viewer with syntax highlighting (Verilog / SystemVerilog), line numbers, copy snippet, and fullscreen code view.
  - Active question panel with ergonomic single-tap radio pills, quick keyboard shortcuts (`1`–`6`, `Y`/`N`), and optional item notes.
- **Autosave & Unbreakable Persistence**:
  - Debounced dual-write autosave: commits to local `IndexedDB`/`localStorage` immediately and syncs with backend Express API over HTTPS.
  - Offline mode indicator with automatic sync-on-reconnect.
  - Unanswered item jump ("Next Unanswered") and interactive item grid palette.
- **Reviewer Self-Service Export & Submission**:
  - Reviewer can download their own filled CSV at any point.
  - Final submission lock with editable re-submit window if enabled by admin.

## 5. Mobile-First & Touch Ergonomics Specification

### 5.1 Ergonomic Thumb Zones
- **Bottom 40% (Natural Reach)**: Next / Previous buttons, "Next Unanswered" trigger, and Question answer selection pills.
- **Middle 30% (Stretch Zone)**: Code snippet preview, question prompt text, and notes textarea.
- **Top 30% (Hard Reach)**: Module ports collapsible details, study metadata, item drawer icon.

### 5.2 Touch Targets & Spatial Math
- **Minimum Tap Target**: All clickable elements (radios, buttons, palette dots, tabs) have a minimum hitbox of $44 \times 44\text{px}$ (primary CTAs $48\text{px}$).
- **Radio Pill Design**: Large pill touch areas with minimum $44\text{px}$ height, clear active background state (`bg-neutral-900 text-white dark:bg-white dark:text-neutral-900`), and visible check prefix (`✓`).
- **Sticky Surface Governance**: Combined top header ($48\text{px}$) and bottom navigation bar ($56\text{px}$) occupy $<15\%$ of a typical $844\text{px}$ mobile screen height, preserving over 85% vertical space for review text.

### 5.3 Responsive Breakpoints
- **Mobile (< 640px)**: Single column, stacked stimulus $\rightarrow$ questions, fixed bottom bar, drawer-based item palette.
- **Tablet (640px – 1024px)**: Single column with wider margins, sticky floating navigation pill bar.
- **Desktop ( $\ge$ 1024px)**: Dual-pane split view (`minmax(0, 3fr) minmax(360px, 2fr)`), sticky right sidebar for questions, independent scroll on left pane.

### 7.2 Backend & Data Persistence Strategy
- **Node.js / Express Architecture**: Single robust full-stack process where Express handles both the API routes (`/api/*`) and serves Vite client assets in development (`vite.middlewares`) and production.
- **Storage Strategy**: A robust, zero-external-dependency transactional database (`data/blinded_portal.json` or SQLite) with atomic file writes (`write-temp-and-rename`) guaranteeing zero corruption during server restarts or concurrent autosaves.
- **Seeded Item Shuffling**: To prevent order monotony across the repeating benchmark requirements (e.g. 5 requirements repeated 60 times each), each reviewer token generates a deterministic pseudorandom seed. The order is shuffled consistently for that reviewer so they can resume seamlessly from any device without order drift.

## 9. Security, Privacy & Blinding Safeguards

1. **Absolute Blinding Enforcement**:
   - The server extraction parser reads JSON files from the ZIP archive and discards `formal_outcome` and `evidence_logs` immediately.
   - Reviewer API endpoints never have access to formal check results, model names, or accuracy scores.
   - Automated regex scrubbing removes any comments matching `ChatGPT`, `OpenAI`, `Anthropic`, `Claude`, or `Gemini` from generated code to prevent branding bias.
2. **Reviewer Data Separation**:
   - Each reviewer token only has read and write access to their own responses.
   - Reviewers have no API route or interface to query other reviewers' answers, email addresses, or progress.
3. **Revocable & Expirable Links**:
   - The Admin can instantly revoke any link with one click, immediately terminating that reviewer's access.
   - All token lookups are verified server-side on every autosave request.
4. **Protection Against Data Loss**:
   - Dual-layer saving: Browser writes to `localStorage`/`IndexedDB` synchronously on every keystroke/radio click, and dispatches a debounced HTTP `POST /api/review/:token/save` request every 500ms.
   - If network disconnects, an offline badge appears, local answers accumulate safely, and sync triggers as soon as the connection is restored.
   - Reviewers can download their answered CSV at any time as an offline hard copy.
5. **Safe File Uploads**:
   - Uploaded ZIP archives are parsed using safe streaming buffers.
   - Directory traversal attacks (e.g. `../../`) are strictly blocked by sanitizing file paths inside the archive.
